EAS 校準模擬第 5–10 次：Windows CPU 版（不用 WSL／Ubuntu）

請在 Windows PowerShell 貼上以下指令，不要先進入 Ubuntu。D:\論文跑須包含原本第 1–4 次 NN 結果與已準備的第 5–10 次共用樣本。

開始 NN 第 5–10 次：
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\論文跑\run-extend-six-windows.ps1" -Method nn

另一台 28 核 Windows 電腦跑 MLE 第 5–10 次（兩台各有一份 D:\論文跑）：
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\論文跑\run-extend-six-windows.ps1" -Method mle
MLE 開始前，該台 D:\論文跑須有相同實驗的第 1–4 次 MLE 結果和第 5–10 次共用樣本；否則程式會停止。
PowerShell 顯示 Detected CPUs 與 CPU slots；若不是預期的 20 或 28，先查工作管理員／處理器親和性。

另開一個 Windows PowerShell 查進度：
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\論文跑\run-extend-six-windows.ps1" -Method status

中斷後，重貼「開始 NN」同一行。已完成的 replicate 會跳過；未完成的 replicate 會重用通過雜湊核對的外層 fold × 係數檢查點。當時正在算、尚未完成的 case 須重算。不要刪除 attempt 資料夾。

第 1–4 次與新結果：
D:\論文跑\outputs_wsl\simulations\eas_four_pair_rl_v1\split_comparison_v1\arms\nn\replicate_001 至 replicate_010
本次日誌：D:\論文跑\outputs_wsl\logs\*_windows_extend_nn.log

outputs_wsl 只是舊結果資料夾名稱；以上 Windows 指令不會執行 WSL。沿用原路徑是為了銜接第 1–4 次，不會重新訓練 NN。第 5–10 次樣本已準備好，目前長時間運算尚未開始。

目前使用 staged CPU 排程，不再按 8 GiB RAM 預算縮減 GP 工作數。每輪最多四個 kernel 可同時比較，20 核時每個最多 5 條矩陣執行緒，28 核時每個最多 7 條；最後單一 GP refit 可用全部可見核心。MLE 格點配適使用全部可見核心數的獨立工作，每個工作 1 條執行緒。候選不足、序列階段與 I/O 仍不保證 CPU 100%。若實體 RAM 不足，Windows 可能換頁、變慢或工作中斷；保留 attempt／checkpoint 後重跑。
