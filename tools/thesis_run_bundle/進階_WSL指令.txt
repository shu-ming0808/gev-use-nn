論文跑：WSL2 / Ubuntu / CPU 版（2026-10-26）
=========================================
不需要 GPU；不搬 Windows .venv。Windows 和 WSL 結果分開。
目前D槽、另一台F槽：只需 cd 正確的論文跑資料夾，後面由腳本自行轉成 /mnt/d 或 /mnt/f。
本機測試 cd "D:\論文跑"；另一台 cd "F:\論文跑"。

目前建議入口：32 GB 自適應資源，Linux MLE+GP 先跑、Linux NN+GP 後跑：
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-linux.ps1
擴充至共 100 次（同一實驗已完成的成對結果會保留）：
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-linux.ps1 -Replicates 100
先完成下方第1步Ubuntu安裝；入口自動確認/安裝Python與uv。
兩條每次共用一組新校準模擬資料；不是重複同一份真實觀測。
首次建立校準曲面的額外時間不納入方法計時；結果總表在outputs_wsl\simulations\本次實驗名稱\mle_comparison_v2_crps。
只檢查不開始：在同一指令後加 -CheckOnly。中斷沿用同Experiment；新計時請換名稱。
預設程序群組排程預算20 GiB、Linux可用RAM保留2 GiB；詳見WSL記憶體設定.txt。
Ultra 7 265：CPU預算18，GP最多4workers×4條，MLE最多16workers×1條，NN4條，最後GP refit8條；函式庫從8條初始化。
候選完成後依記憶體餘裕補工作，保持候選結果順序；當剩餘任務少或有循序計算時，CPU仍不會全滿。記憶體不足時僅在沒有執行中任務的情況降至一個worker，不保證避免OOM。
舊run-three.ps1仍保留，僅供明確需要Windows／Linux三方法歷史對照時使用。

1. 若另一台沒有 WSL：管理員 PowerShell 執行
wsl --install -d Ubuntu-24.04
依Windows提示重新開機。開啟 Ubuntu，完成第一次 Linux 使用者與密碼設定。
這不是 ERA5 金鑰。之後一般 PowerShell 即可，不需一直用管理員。

2. 安裝 Linux Python 3.10.20、uv 與固定 CPU 套件，驗證資料
cd "F:\論文跑"
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-wsl.ps1
第一次需網路。腳本只安裝環境、複製已準備輸入並跑 check，不啟動完整GP。
若已有Ubuntu卻沒有curl，在Ubuntu執行 sudo apt-get update && sudo apt-get install -y curl ca-certificates。

3. 只檢查（不跑完整流程）
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-wsl.ps1 -Mode check

4. EAS 真實資料重新跑一趟，保留舊結果
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-wsl.ps1 -Mode eas -NewRun -ParallelMode adaptive -RefitThreads 8
仍是全部7822格、原NN、5外折/3內折/500km，新的分階段CPU配置。
此指令Jobs=4、Threads=8、每工作最多4矩陣執行緒、最後refit8條；不改NN或空間模型。
例如需要限制總CPU預算，可在任何指令後加 -CpuBudget 12。
若要對照舊計算排程，加 -ParallelMode fixed -Threads 1。

5. 校準模擬一次（生成新50年序列，不是重跑真實資料）
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-wsl.ps1 -Mode simulate -Replicates 1 -Experiment eas_wsl_u265_v1

6. 同一設定擴充到100次
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-wsl.ps1 -Mode simulate -Replicates 100 -Experiment eas_wsl_u265_v1
已完成、hash和protocol一致才跳過。改設定請換Experiment名稱。
驗證通過的舊Windows EAS可作校準來源，不用為了校準再跑一次真實資料。
舊Windows成果不會宣稱為Linux計時。

7. NN與MLE兩條完整模擬流程比較（先1次確認）
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-linux.ps1 -Replicates 1 -Experiment paired_u265_v1
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-linux.ps1 -Replicates 100 -Experiment paired_u265_v1
兩方法使用同一批模擬觀測、相同folds及執行資源策略；MLE工作數由CPU/RAM動態決定。
不拿舊Windows NN耗時配新Linux MLE耗時來宣稱加速比。

8. 全球：先轉換各區參數，再診斷folds/buffer
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-wsl.ps1 -Mode global -Workers 2 -ParallelMode adaptive -RefitThreads 8
原始資料仍須在 F:\論文資料\ERA5\global_predictors_1976_2025。
各區診斷後會停在 awaiting_buffer_fold_approval；不是自動套用EAS的500km。
審核並另存 region_settings.approved.json 後：
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-wsl.ps1 -Mode global -SkipPreprocess -Settings .\outputs_wsl\global\region_settings.approved.json -ParallelMode adaptive -RefitThreads 8
WSL預處理獨立，沒有自動共用Windows月快取；不要同時啟動兩邊讀寫同一輸出。

9. 看進度
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-wsl.ps1 -Mode status
日誌在 .\outputs_wsl\logs；各趟 execution_phases.json 有候選/重新配適耗時及記憶體樣本。
